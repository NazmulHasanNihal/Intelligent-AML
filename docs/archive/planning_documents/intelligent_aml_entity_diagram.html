Layer 1

Data Ingestion & Graph Construction

Raw, high-volume transaction logs are streamed — never loaded fully into memory — and transformed into a heterogeneous graph representation that preserves both entities and their relationships.

«input»Raw Data Sources
•Bank wire transfer logs
•Mobile Financial Services (MFS) records
•Cryptocurrency transaction logs
streamed lazily via
«process»Processing Engine
•Polars (Rust) — zero-copy, lazy execution
•DuckDB — in-process SQL analytics
•Prevents out-of-memory (OOM) crashes at scale
constructs
«output»Heterogeneous Graph Tensor
Node Types (V)
•Account · User · Device · Institution
Edge Types (E)
•Transaction · IP Connection · Shared Ownership

Layer 2

Detection & Data Rebalancing

Fraud is rare, so the training set is synthetically rebalanced before the temporal graph model performs inference and risk scoring.

«input»Imbalanced Transaction Set
•~97% legitimate transactions
•~3% fraudulent transactions
•Severe imbalance limits model recall
rebalanced by
«process»Wasserstein GraphGAN
•Synthesizes minority-class fraud subgraphs
•Preserves structural / topological realism
scored by
«process»HT-GNN Inference Core
•Heterogeneous Temporal Graph Neural Network
•Burst-Aware Edge Attenuation mechanism
•Flags rapid micro-transaction spikes (smurfing)
produces
«output»Risk-Scored Transactions
•Per-node fraud probability
•Ranked investigation candidates

Layer 3

Federated Privacy

Model intelligence is shared across institutions without ever moving the underlying customer data — each bank keeps its data local.

«input» (×N)Distributed Bank Silos
•Silo A — local institution records
•Silo B — local institution records
•Silo C — local institution records
•Raw data never leaves its silo
local training via
«process»Federated Learning Core
•Flower — orchestrates federated training rounds
•Opacus — injects differential-privacy noise into gradients
aggregates into
«output»Global Federated Model
•Shared model weights only — no raw data
•Privacy-preserving, cross-institution intelligence

Layer 4

Causal Auditing / Explainability (XAI)

Every high-risk flag is made auditable: the model must show why it raised the alarm, not just that it did.

«input»High-Risk Node Alert
•Emitted when HT-GNN risk score crosses threshold
isolated by
«process»GNNExplainer
•Computes the minimal causal subgraph behind the alert
•Ranks contributing nodes & edges by importance
rendered as
«output»Visual Heatmap (PyVis)
•Interactive graph of the exact transaction chain
•Investigator-facing, EU AI Act-aligned explanation

Layer 5

Agentic SAR Automation

A two-agent pipeline turns explainable evidence into a structured, regulation-ready Suspicious Activity Report (SAR).

«input»XAI Evidence Package
•Causal subgraph + heatmap + risk metadata
analyzed by
«agent»Agent 1 — Evidence Analyst
•Built on CrewAI + LangChain
•Cross-references patterns against BFIU / global statutes
drafted by
«agent»Agent 2 — Narrative Writer
•Compiles findings into a regulatory narrative
•Formats the structured document via ReportLab
outputs
«output»Draft SAR (PDF)
•Regulation-ready Suspicious Activity Report
